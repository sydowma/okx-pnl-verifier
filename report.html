三、完整计算公式与动态架构流程图

点击下方标签页切换查看两套方案的完整数学公式（精确到 OKX 字段名与正反向合约差异）：

【步骤 1：结算币种折算 USD 汇率 P_usd(ccy, t)】 • 稳定币 (ccy ∈ {USD, USDT, USDC})：P_usd = 1.0 • 币本位 (ccy ∈ {BTC, ETH, ...})： - 持仓实时计算：P_usd = ws.idxPx（兜底 ws.markPx，0 REST） - 平仓落袋计算：P_usd = IndexCandle(ccy-USD, uTime) 【步骤 2：有符号持仓张数 Q(p) 与 T0 时刻未实现盈亏 UPL_usd(p, T0)】 • Q(p) 规则：posSide=="net" → pos；posSide=="long" → +|pos|；posSide=="short" → -|pos| • 正向合约 (ctType == "linear"，如 BTC-USDT-SWAP / BTC-USD_UM-261225)： UPL_usd(p, T0) = Q(p) × ctVal × (markPx(T0) - avgPx) × P_usd(ccy, T0) • 反向/币本位合约 (ctType == "inverse"，如 BTC-USD-SWAP / BTC-USD-261225)： UPL_usd(p, T0) = Q(p) × ctVal × (1 / avgPx - 1 / markPx(T0)) × P_usd(ccy, T0) 【步骤 3：月初 0 点基线快照（仅对 T0 时刻未平仓位 cTime < T0）】 SnapshotPnL(p, T0) = realizedPnl(p, T0) × P_usd(ccy, T0) + UPL_usd(p, T0) ※ 注意：OKX 的 realizedPnl 已包含 pnl + fee + fundingFee + liqPenalty + settledPnl，切勿重复加减手续费！ 【步骤 4：单仓位本月贡献 MonthPnL(p)】 • 本月已平仓 (positions-history，按 (posId, cTime) 精确匹配)： MonthPnL_closed(p) = realizedPnl_final × P_usd(ccy, uTime) - (cTime < T0 ? SnapshotPnL(p, T0) : 0) • 当前未平仓 (WS positions 实时推送)： MonthPnL_open(p) = (realizedPnl_now + upl_now) × P_usd(ccy, Now) - (cTime < T0 ? SnapshotPnL(p, T0) : 0) 【步骤 5：用户月度总 PnL】 MonthlyPnL_user = Σ MonthPnL_closed(p) + Σ MonthPnL_open(p) （等价用户级简写：Σ LifetimePnL_closed + Σ LifetimePnL_open - UserSnapshotPnL_at_T0）
【核心公式】 MonthlyPnL_equity = totalEq(Now) - NetTransfers(T0, Now] - totalEq(T0) 【净划转（仅查 bills-archive?type=1，按天聚合为 daily_net_transfer_usd）】 DailyNetTransfer(day) = Σ [ bill.balChg × P_usd(bill.ccy, bill.ts) ] (balChg > 0 转入，< 0 转出) NetTransfers(T0, Now] = Σ DailyNetTransfer(day) (最多 30 条日聚合记录相加) 【缺失 totalEq(T0) 快照时的还原公式】 totalEq(T0) = Σ [ CashBal_c(T0) × P_usd(c, T0) ] + Σ UPL_usd(p, T0) ※ CashBal_c(T0) 直接取 GET /api/v5/account/bills-archive?ccy=c&end=T0&limit=1 返回的 bal 字段（1 次请求，免分页）

四、核心边界：必须从当月 1 号 0 点起算，缺失快照怎么处理？

在硬性要求从当月 1 号 00:00（T0）起算的前提下：所有月内新开仓位（cTime >= T0）直接用 positions + positions-history 即为 100% 精确。唯一需要处理的是跨月老仓位（cTime < T0）：

场景与策略 所需接口 精度评级 具体做法与差异说明
常规场景：有 1 号 0 点快照 纯 positions（零 bills） 100% 精确 1 日 00:00 落库 realizedPnl + upl，整月扣减基线，误差 $0.0000。
无快照 — 策略 A：纯 positions 近似 positions + markPx(T0) K 线 UPL 精确，2 项偏差 剥离 T0 前价格浮盈，但无法剥离 T0 前开仓/资金费及跨期加减仓。
无快照 — 策略 B：按需 1 次精准补齐 仅对该 instId 调 1 次 fills + bills-archive 100% 精确 冷启动补齐 T0 基线落库，此后永久切回纯 WS 增量，日常零 bills。

4.1 为什么无 1 号快照时，只用 positions 无法做到 100% 精确？

1. 无历史时刻快照接口：GET /positions 只返回此刻（Now）状态，不支持 asOf=11月1日00:00。
2. 费用与部分平仓盈亏为全生命周期累计数：fee / fundingFee / realizedPnl 从 cTime 累加至今，单靠仓位接口无法拆出 10 月与 11 月各占多少。
3. 跨期加减仓无法唯一反推 pos(T0) 与 avgPx(T0)：10 月开 10 张、11 月加 5 张再平 8 张后，当前只剩 7 张，必须靠 fills-history 倒推 1 号 0 点的精确张数与均价。

4.2 账单（bills-archive）还原月初快照的原理、字段与查询范围

核心原理：OKX 交易账户账单类似银行流水账——任何改变现金余额的事件（平仓盈亏、手续费、资金费、划转、强平）都会记录一笔流水，且每一行都带有变动后的精确余额 bal 与变动额 balChg。因此可通过以下两种方式还原 CashBal(T0)（注意：未平仓浮盈 UPL(T0) 尚未进账单，需另由跨月持仓 + markPx(T0) 补齐）：

  • 方法 1（最快，推荐）：直接查 ts <= T0 的最新 1 条账单，读取其 bal 字段即为 CashBal(T0)（每币种仅 1 次请求，免分页）。
  • 方法 2（兜底）：若 T0 之前 3 个月无账单，则倒推 CashBal(T0) = CashBal(Now) - Σ balChg(T0, Now]。

用到的 5 个账单字段：ccy（币种）、ts（时间戳）、bal（变动后账户余额）、balChg（本笔变动额）、type（账单类型，如 1=划转、2=交易、8=资金费）。

如果用户有 N 个 instId，需要遍历 N 次吗？不需要！

4.3 跨月仓位 UPL(T0) 零误差还原案例（直观验证）

【真实交易过程（假设 11 月 1 日 00:00 未拍快照）】 • 10 月 25 日：初始现金 $10,000，开多 1 BTC（100张, ctVal=0.01）@ $60,000，开仓费 -$30 → 现金变为 $9,970 • 11 月 1 日 00:00 (T0)：BTC 标记价 = $65,000 → 真实 totalEq(T0) = $9,970 (现金) + 1 × ($65,000 - $60,000) (UPL) = $14,970 • 11 月 10 日：在 $68,000 全平，平仓费 -$34 → 现金变为 $9,970 + $8,000 - $34 = $17,936 → 真实 11 月 PnL = $17,936 - $14,970 = +$2,966（即 11 月涨幅 +$3,000 扣除 11 月平仓费 -$34） 【无快照还原步骤（误差 = $0.00）】 1. Cash(T0)：调 bills-archive?ccy=USDT&end=T0&limit=1 → 直接拿到 bal = $9,970（10 月 -$30 开仓费已自动扣完！） 2. Q(T0) & avgPx(T0)：由 positions-history + fills-history(T0→Now) 还原 → 1 BTC @ $60,000 3. markPx(T0)：由 history-mark-price-candles（00:00:00 1m K 线开盘价）拿到 → $65,000 4. UPL(T0) = 100 × 0.01 × ($65,000 - $60,000) = +$5,000 → 还原 totalEq(T0) = $9,970 + $5,000 = $14,970 5. 还原 11 月 PnL = $17,936 - $14,970 = +$2,966 → 与真实值完全一致（误差 $0.00）！ 【唯一会产生误差的 2 种边界情况】 1. 跨月仓位在 T0 之后既有加仓又有部分平仓，但跳过 fills-history 未倒推； 2. 该跨月仓位开仓时间超过 3 个月（超出 OKX fills-history 保留期）且在 T0 之后反复加减仓。

九、上线前 5 大必避 OKX 深坑

1. WS pos=="0" 清空盈亏 + 1–2s 历史索引延迟：用 pending_close 防抖 + 持久化延迟队列按 (posId, cTime) 精确匹配。
2. posId 跨交易复用：绝对不能只用 posId 判重，必须绑定 cTime。
3. WS fills 频道有 VIP 门槛（64003）：散户榜单不要依赖 fills WS。
4. bills 仅保留 7 天：查 1 个月账单/划转必须用 bills-archive（保留 3 个月）。
5. WS 8443 端口即将下线：直接使用 443 端口并在鉴权循环跳过 code: 64010 的 notice 帧。
