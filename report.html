一、执行摘要（Executive Summary）

最终推荐主方案：优化版 totalEq 权益法 + 按日聚合 type=1 划转 + 私有 WS account

1. 为什么必须采用 totalEq 主方案：实盘测试确认，OKX 的 positions / positions-history 与 WS positions 对现货交易均返回 0 条记录；只要榜单需要纳入现货，totalEq(Now) - NetTransfers - totalEq(T0) 是唯一能统一覆盖「现货 + 全部合约」且状态机最简洁的方案。

2. 彻底解决「账单数据量大」问题：日常划转只查 type=1（subType ∈ {"11","12"}）并按天聚合为 daily_net_transfer_usd（通常不足 1 页/月）；月中新用户无快照还原时，通过 balance ∪ SPOT fills ∪ type=1 bills 精准拿全 ccy list（通常 2～8 个币种），每币种调 1 次 end=T0&limit=1 直接读 bal，无需全量分页账单。

3. 实测精度与 10 万级性能：现货跨期持仓 + 清仓 + 划转实测 SOL/USDT 还原误差 0.000000、totalEq(T0) 精度 99.9957%（误差仅 0.0043%）；10 万用户量级单事件计算 O(1)，且无需维护复杂的 pos=="0" 延迟队列。

二、核心数学公式（精确到 OKX 接口与字段）

【1. 核心月度 PnL 公式（统一覆盖现货 + 杠杆 + 所有合约 + 期权）】 MonthlyPnL(T0 → Now) = totalEq(Now) - NetTransfers(T0, Now] - totalEq(T0) ※ totalEq(Now)：由私有 WS `account` 频道实时推送（O(1) 内存更新，无需全平延迟队列） 【2. 净划转 NetTransfers（查 bills-archive?type=1，代码过滤 subType ∈ {"11","12"}，按天聚合）】 • subType == "11"：转入交易账户（balChg > 0）；subType == "12"：转出交易账户（balChg < 0） • DailyNetTransfer(day) = Σ [ bill.balChg × IndexPx(bill.ccy-USD, bill.ts) ] • NetTransfers(T0, Now] = Σ DailyNetTransfer(day) （全月最多 30 条日聚合记录相加） 【3. 缺失 totalEq(T0) 快照时的还原公式（仅月中新用户冷启动执行 1 次）】 totalEq(T0) = Σ [ CashBal_c(T0) × IndexPx(c-USD, T0) ] + Σ UPL_usd(跨月合约 p, T0) ① 精准拿全用户 ccy_list（无需遍历 300+ 币种，完全跳过高频合约账单）： CCY(T0) = { GET /account/balance 当前非零币种 } ∪ { fills-history?instType=SPOT&begin=T0&end=Now 现货交易涉及币种（抓出已卖空归零币种） } ∪ { bills-archive?type=1&begin=T0&end=Now 划转涉及币种（抓出已转空归零币种） } ② 每币种 1 次请求拿 CashBal_c(T0)： GET /api/v5/account/bills-archive?ccy=c&end=T0&limit=1 → 直接读 bal 字段（免分页！） ※ 稳定币估值也取 USDT-USD / USDC-USD 1m 指数 K 线（消除 ~0.1% 折溢价误差） ③ 跨月未平合约（cTime < T0）的 UPL_usd(p, T0)（必须经 fills-history 还原 Q(T0) 与 avgPx(T0)）： • 查 GET /api/v5/trade/fills-history?instType=...&instId=<跨月合约>&begin=T0&end=Now • Q(T0) = Q(Now) - Σ fill_signed_sz(T0, Now] （buy=+fillSz, sell=-fillSz；全平则 Q(Now)=0） • 正向合约 (linear)： UPL_usd(p, T0) = Q(T0) × ctVal × (markPx(T0) - avgPx(T0)) × IndexPx(ccy-USD, T0) • 反向/币本位 (inverse)：UPL_usd(p, T0) = Q(T0) × ctVal × (1/avgPx(T0) - 1/markPx(T0)) × IndexPx(ccy-USD, T0)

四、无 1 号快照还原原理：bills-archive + ccy list + 跨月 UPL(T0)

4.1 为什么不需要遍历 300+ 币种，也不需要分页高频合约账单？

从余额守恒可知：一个币种如果在 T0 余额 > 0，到 Now 要么仍有余额（在 /account/balance 里），要么在 (T0, Now] 期间被现货卖空或转出归零。因此只需取 3 个轻量接口的并集即可 100% 拿全 ccy list（通常仅 2～8 个币种）：

查询目标 接口与过滤条件 时间范围 开销说明
当前非零币种 GET /api/v5/account/balance 实时（Now） 1 次请求
卖空归零的现货币种 fills-history?instType=SPOT begin=T0, end=Now 仅查现货，跳过高频合约
转空归零的币种 & 净划转 bills-archive?type=1（过滤 subType∈{11,12}） begin=T0, end=Now 通常 <1 页（0～20 条）
每个币种的 CashBal(T0) bills-archive?ccy=c&end=T0&limit=1 ts <= T0（近 3 个月内） 每币种 1 次，直接读 bal
跨月合约 UPL(T0) fills-history?instId=<跨月合约> + markPx(T0) begin=T0, end=Now 仅针对 cTime < T0 合约

用到的 6 个账单字段：ccy（币种）、ts（时间戳）、bal（变动后余额）、balChg（变动额）、type（1=划转）、subType（11=转入，12=转出）。

4.2 跨月合约 UPL(T0) 零误差还原数值案例

【真实交易过程（11 月 1 日 00:00 未拍快照）】 • 10 月 25 日：初始现金 $10,000，开多 1 BTC（100张, ctVal=0.01）@ $60,000，开仓费 -$30 → 现金 $9,970 • 11 月 1 日 00:00 (T0)：BTC 标记价 = $65,000 → 真实 totalEq(T0) = $9,970 + $5,000 = $14,970 • 11 月 10 日：在 $68,000 全平，平仓费 -$34 → 现金 $17,936 → 真实 11 月 PnL = $17,936 - $14,970 = +$2,966 【无快照还原步骤（误差 = $0.00）】 1. Cash(T0)：bills-archive?ccy=USDT&end=T0&limit=1 → 直接拿 bal = $9,970（10 月 -$30 开仓费已自动扣完！） 2. Q(T0) & avgPx(T0)：必经 fills-history(T0→Now) 还原（防部分成交/加减仓）→ 1 BTC @ $60,000 3. markPx(T0)：history-mark-price-candles（00:00:00 1m 开盘价）→ $65,000 4. UPL(T0) = 100 × 0.01 × ($65,000 - $60,000) = +$5,000 → 还原 totalEq(T0) = $14,970 5. 还原 11 月 PnL = $17,936 - $14,970 = +$2,966（与真实值完全一致，误差 $0.00！）

五、10 万用户生产落库方案（双场景 + 重启容灾）

  • 场景一（1 号 0 点前提前上线 10 万存量用户）：T0 前 60～5 分钟平滑预热每个用户的 cashBal + 活跃合约 (pos, avgPx) 并建立 WS account 连接（~30–55 QPS）；00:00:00.000 冻结 1 份全市场共享 idxPx(T0) + markPx(T0) 表，本地毫秒级统一重算所有 10 万用户的 totalEq(T0) 批量落库（0 次 0 点 REST 尖峰，0ms 横截面价格偏移）。
  • 场景二（1 号～30 号月中新插入用户）：冷启动执行一次「第四节无快照还原」写入 monthly_equity_snapshots 与 daily_net_transfers，随后接入 WS account 永久同构运行。
  • 服务重启容灾：重启后直接从 DB 加载 monthly_equity_snapshots 与 daily_net_transfers，重连 WS account 自动收到最新 totalEq(Now)，并按 last_sync_ts 补齐重启窗口内可能发生的 type=1 划转即可。

七、上线前必避的 5 个 OKX 接口深坑

1. GET /api/v5/account/bills 仅保留近 7 天：回溯 1 个月账单/划转必须调用 GET /api/v5/account/bills-archive（保留近 3 个月）；近期 7 天内的实时账单优先查 bills。
2. 划转过滤必须精确：REST 传 type=1 一次拉回转入与转出，代码侧再过滤 subType ∈ {"11", "12"}，防止交易账户内部保证金划拨误算。
3. 稳定币估值别硬编码 1.00：OKX 计算 totalEq 时按实时 USDT-USD（如 0.9985）指数折算，还原 totalEq(T0) 时同步拉取 USDT-USD / USDC-USD 指数 K 线即可消除 $3 级别折溢价偏差。
4. WS 8443 端口即将下线：直接使用 443 端口（wss://ws.okx.com/ws/v5/private），并在鉴权收包循环中跳过 code: 64010 的 notice 帧。
5. WS fills 频道有 VIP 门槛（64003）：普通散户无法订阅，切勿依赖。
附录（已归档，非当前主方案）：纯合约仓位增量法（positions + WS，不含现货）

说明：由于新需求明确需要包含现货，而 OKX positions / positions-history / WS positions 均不包含现货（实测返回 0 条），本方案已降级为备选归档，仅适用于未来若单独开设「纯合约榜单」的场景。

  • 公式：MonthlyPnL = Σ closed_realizedPnl + Σ open_(realizedPnl + upl) - T0_pos_snapshot（全品类实测 USDT 永续、币本位永续 BTC-USD-SWAP、币本位交割 BTC-USD-261225、USDC 结算交割 BTC-USD_UM-261225，WS 增量与 REST 对账误差均为 $0.0000）。
  • 必避深坑：① WS 全平帧（pos=="0"）会清空 realizedPnl 为 ""，需 pending_close + 延迟队列查 positions-history；② OKX 会跨交易复用同一个 posId，延迟队列必须严格匹配 (posId, cTime)；③ 币本位合约需用 WS idxPx 实时折算 USD。
